# BERTIE — Cardputer ADV firmware

BERTIE is a custom firmware for the **M5Stack Cardputer ADV**, used as a portable keyboard/display terminal in a local bindery-assistant system. This repository contains the Cardputer terminal firmware, not the central BERTIE AI service.

## Current features

- Compact main screen with battery percentage, Wi-Fi status and firmware/build number.
- Fixed display rotation (`setRotation(0)`).
- GitHub Releases firmware updates over verified HTTPS, initiated on the device.
- On-demand emergency Wi-Fi access point and browser-based firmware uploader.
- Wi-Fi disabled at normal startup and after update checks where possible to reduce battery drain.
- OTA-compatible flash partition layout with two application slots.

## Cardputer controls

| Keys | Action |
| --- | --- |
| **Fn + U** | Connect to saved Wi-Fi and check the latest GitHub release. Press **Enter** to install, or **Backspace** to cancel. |
| **Fn + P** | Toggle the `BERTIE-UPDATE` emergency access point. Its password and the updater address are shown on screen when enabled. |

The emergency access point turns off after **10 minutes without web activity** (and is not timed out during an active firmware upload). It is **off at boot**. There are no automatic background GitHub checks.

## Normal update workflow (GitHub OTA)

1. Make and test source changes in Codespaces.
2. Commit and push the source to `main`.
3. Check [GitHub Actions](https://github.com/jchistory/advFirmware/actions) for a successful **Build and publish BERTIE firmware** run.
4. Confirm a new [GitHub Release](https://github.com/jchistory/advFirmware/releases) contains `firmware.bin`.
5. On BERTIE, press **Fn + U**. Review the offered build number, then press **Enter** to install.
6. Keep BERTIE powered until the firmware installs and the device reboots.

GitHub Actions embeds the workflow run number as `BERTIE_BUILD_NUMBER` and publishes an application-only `firmware.bin` asset. Firmware compiled locally without that header displays **build 0**.

**Important:** The Cardputer needs access to a saved 2.4 GHz Wi-Fi network with working internet and NTP time synchronisation. The current firmware stores **one** Wi-Fi network in device preferences; it does not yet automatically choose between several home routers. If clock sync fails, retry the check.

## First-time Wi-Fi setup and emergency browser OTA

1. Press **Fn + P** to turn on the `BERTIE-UPDATE` access point.
2. Read the access-point password from BERTIE's screen, then connect a computer or phone to that Wi-Fi network.
3. Open **http://192.168.4.1**.
4. Enter a 2.4 GHz network SSID and password and save them on BERTIE, if needed.
5. For emergency firmware recovery, upload an **application-only** `.bin` file using the browser form.
6. Press **Fn + P** again to disable the access point when finished.

**Never upload the merged USB recovery image through the browser updater.** BERTIE's stored Wi-Fi password is kept in ESP32 nonvolatile storage; it should never be committed to GitHub.

## Build in Codespaces

The project uses PlatformIO, Arduino-ESP32 via PioArduino, M5Cardputer, ArduinoJson and ESP32CertBundle. The existing Codespaces environment has a local `.venv` containing PlatformIO.

```bash
bash build.sh
```

The script compiles the firmware and creates:

| File | Use |
| --- | --- |
| `bertie-v0.3-ota.bin` | Application-only image for browser OTA. |
| `bertie-v0.3-merged.bin` | USB recovery image, flashed at offset `0x0`. |

The filenames currently contain `v0.3`; the GitHub release build number is separate. If the full merged image is needed, use a compatible ESP32-S3 flashing tool and the correct flash offset. USB recovery can require reconfiguring device preferences depending on how the flash is erased.

### Build configuration

- Target: **ESP32-S3**, 8 MB flash.
- OTA partitions: `app0` at `0x10000` and `app1` at `0x340000`, each **3264 KB**.
- GitHub Actions builds from `.github/workflows/publish-firmware.yml` and publishes `firmware.bin` to the latest numbered release.

## Repository layout

```text
.github/workflows/publish-firmware.yml  GitHub release build
.vscode/                               Codespaces editor/build settings
src/main.cpp                           Cardputer application
platformio.ini                         PlatformIO board, framework and libraries
build.sh                               Local build and USB recovery packaging
.gitignore                             Excludes local secrets, tools and binary outputs
README.md                              This document
```

`include/build_version.h` is generated by GitHub Actions, and `include/secrets.h` is an optional **local-only** header. Both are ignored by Git; never commit passwords or local secrets.

## Troubleshooting

- **Fn + U says `Clock sync failed`:** The clock must be set for HTTPS certificate verification. Try again when the Wi-Fi connection is stable.
- **Emergency network not visible:** Press **Fn + P**; the AP is intentionally disabled at boot and turns off after inactivity.
- **Need a fallback:** Use the emergency browser OTA page or the merged USB recovery firmware.
- **Serial diagnostics:** Use USB serial at **115200 baud**.

## Status

GitHub OTA, on-demand emergency Wi-Fi and the compact screen have been tested on the Cardputer ADV. This remains an evolving terminal prototype for the wider BERTIE system.
